HIL ML Ops agent

An LLM-assisted test pipeline for a HIL bench where rules decide and LLMs draft: requirements and a DBC go in; test specs, scripts, bench results, root-cause drafts and Jira tickets come out, with a human approving each step.

This is my personal rebuild on synthetic ACC data, made so the approach can be shown outside my employer. The original proof of concept runs on a real dSPACE SCALEXIO rig at work; it's described on the deep-dive page.

01 / The pipeline

DOORS export (ReqIF/CSV) + DBC
 → 00 parse (rules) → 01 design (LLM specs) → 02 ISTQB test design (LLM test-basis model; code derives EP/BVA/DT/ST cases)
 → 03 functional-safety derivation (LLM HARA; rules for bus faults)        ── gate: HARA lock
 → ECU script review                                                      ── gate: script review
 → 04 execute on a virtual CAN bench → 05 observe (decode, timeline)
 → 06 close the loop: LLM compare, hybrid RAG + LLM root-cause draft, ticket drafts   ── gate: publish approval
 → 11 publish: Jira issues, RCA indexed back into RAG, verification report

03 / What's built

  • Grounding on every LLM output: schema validation, DBC allow-list, a script grammar and lint (values inside DBC range, every stimulus set before the first check, each output seen in at least two states), computed boundary values, and claim checks so an RCA can only quote values this run actually applied.
  • Virtual bench: python-can with a simulated ACC ECU and injectable faults: threshold errors, ignored brake or deactivate button, frame loss, E2E CRC and counter faults, CAN fault confinement and bus-off recovery, and a virtual fault-insertion unit (open, short to ground or battery) on the CAN lines.
  • Test design standards in code: ISTQB techniques, ISO 26262-4 integration methods per ASIL, and my own derivation ladder (signal enumerations → pins → bus → message → signal) built from the DBC.
  • Hybrid RAG: BM25 + local embeddings (nomic-embed-text) fused by reciprocal rank, over Jira and Confluence Cloud; approved RCAs are indexed back so the same root cause isn't solved twice.
  • Cost-first routing: stages ask for a tier, not a vendor; local Ollama, free cloud tiers or GPT-4o mini under a per-run cost cap. A full live campaign cost under one US cent.
  • Evidence: per-stage manifests (model, prompt hash, approver), an audit log, eval scores and a traceability report; 78 automated tests.

04 / Live runs (synthetic requirements)

Run against a real Jira/Confluence Cloud site: 14 requirements up to ASIL-B placeholders, up to 144 derived cases per cycle. The bench caught every seeded fault; each failure became a new Jira defect or a comment on the open one, depending on the deciding input. I rejected drafts at the gates several times (an inverted hazard, a missing check), and each rejection reason was fed into the redraft.
