Detailed stage flow
  1. Design — DOORS NG → GPT-4o integration diagrams (Python API) → rule-based real vs soft on SCALEXIO → GPT-4o-mini test specs (JSON schema)
  2. Functional derive — llama3.2 (Ollama) signal enumeration & ISTQB EP/BVA → rule-based platform sanity → ECU pin faults → GPT-4o ECU Test scripts
  3. FuSa derive — rule-based ASIL promotion → GPT-4o HARA cases (human sign-off) → GPT-4o-mini bus/message fault expansion
  4. Execute & observe — SCALEXIO / ECU Test → in-house CAN Analyzer decode (Python)
  5. Agentic close-loop — GPT-4o compare vs DOORS NG → nomic-embed-text RAG on JIRA/Confluence → GPT-4o RCA → GPT-4o-mini draft tickets (human approve)

How it stitches together

  1. Python orchestrator in VS Code writes stage artifacts to campaign/00…11/ folders
  2. High-reasoning steps (diagrams, HARA, compare, RCA) via OpenAI-compatible API from Python; bulk ISTQB + embeddings via Ollama
  3. Human gates: after diagrams, after HARA lock, after ECU Test scripts, before JIRA/Confluence publish
  4. LLMs never invent signal IDs or ASIL levels — only DOORS, ARXML/DBC, and the CAN Analyzer ground truth
