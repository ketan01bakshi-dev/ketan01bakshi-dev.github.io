Detailed stage flow
  1. Model — the LLM (GPT-4o / GPT-4o mini) drafts only a test-basis model from the requirement text: conditions, transitions, "otherwise" rules, declared assumptions. A validator checks it against the DBC and the requirement and returns every error in one repair round.
  2. Derive — code derives the tests: ISTQB techniques (equivalence partitions, boundary values, decision tables, state transitions, scenarios), ISO 26262-4 integration-test methods per ASIL, and a derivation ladder from signal enumerations to pin faults to bus, message and signal level.
  3. Gate — a human signs off the HARA lock and the script review; each approval is bound to the artifact's SHA-256 hash, and a rejection note travels with the redraft.
  4. Execute — a bench health gate runs before every campaign; the Python orchestrator then drives ECU-TEST, which talks to SCALEXIO over the XIL API (plant-model variables, restbus manipulation, fault insertion unit). Timing checks use windows sized from measured latency; the runner, not the LLM, decides pass or fail.
  5. Close-loop — each failure gets a deciding-input signature (new ticket vs comment on an open defect); RAG over Jira/Confluence history surfaces prior similar defects; the LLM drafts the RCA and ticket, claims the bench didn't observe are rejected, and a human approves before anything is published.

How it stitches together

graph TD A[Requirements + DBC] -->|GPT-4o / 4o mini| B[Test-basis model] B -->|Validator rules| C[Validated model] C -->|Code: ISTQB + ISO 26262-4| D[Test cases + scripts] D -->|Human: HARA lock + script review| E[Approved campaign] E -->|Bench health gate| F[ECU-TEST] F -->|XIL API| G[SCALEXIO rig] G -->|Runner verdicts| H[Results] H -->|Deciding-input signature| I[Failure signature] I -->|RAG: Jira / Confluence| J[Prior similar defects] J -->|GPT-4o, fact-checked| K[RCA + ticket drafts] K -->|Human: publish approval| L[Jira / Confluence]
  1. One Python orchestrator generates and gates the tests and drives execution through ECU-TEST, which also reports the results
  2. The LLM drafts a model and the RCA text; code derives every test and the runner decides every verdict
  3. Human gates: HARA lock, script review, publish approval, each bound to the artifact's hash
  4. GPT-4o, the RAG and its embeddings run inside a sandboxed Daimler environment, set up with Daimler IT; data never leaves the company
